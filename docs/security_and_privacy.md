# 隐私与公开发布

## 先分四类

- 可公开代码：通用程序、空白配置、虚构示例、通用文档。
- 社群内部内容：指南正文、讨论、活动地址、成员贡献。
- 个人信息：姓名、账号、联系方式、头像、学号、行为记录。
- 凭据与基础设施：API Key、Cookie 密钥、邀请码、域名后台、服务器 IP、对象存储地址。

公共 Git 仓库原则上只放第一类。其余内容即使“已经在群里发过”，也不等于获得了公开许可。

## 公开前的双重检查

先运行自动扫描：

```bash
python skills/build-community-hub/scripts/audit_public.py .
```

再由人逐项检查：Git 历史、图片与文档元数据、示例账号、测试夹具、部署文件、Issue 截图、域名/IP、对象存储 bucket、组织专属提示词和真实内容片段。

如果源项目曾含敏感数据，不要只删除当前文件后继续公开原历史。新建无历史的干净发行仓，并在第一笔 commit 前扫描。

## 使用外部模型

把“允许发送给模型的数据”写进社群规则。默认不要发送成员私聊、成绩、健康、身份信息、未公开文档或完整原始附件。能在本地做的解析优先本地做；发送前最小化、去标识化，并记录使用了哪个提供方。

## 备份与删除

备份必须加密、限制访问并定期做恢复演练。成员提出删除或撤回时，要能定位正文、附件、索引、缓存和历史版本中的副本，并明确依法或为审计必须保留的范围。
