# 部署选择

## 先本地，后联网

本地模式足以完成需求验证，不需要云账号。只有社群已经确定管理员、隐私边界、备份责任和每月预算后，才进入联网部署。

## 三种路径

| 路径 | 适合 | 代价 |
|---|---|---|
| 一台成员电脑本地运行 | 访谈、演示、小范围试用 | 电脑关闭后不可访问 |
| 托管应用平台 | 缺少运维经验的小社群 | 平台约束与持续费用 |
| VPS + HTTPS + 私有对象存储 | 需要长期控制和迁移能力 | 需要更新、监控、备份和值守 |

模板不绑定托管平台。Agent 应根据用户所在地区、预算、数据敏感度和维护能力查阅当时的官方文档后给出选择；部署价格和规则会变化，不能照抄旧教程。

## 上线门槛

- 生产配置与代码分离，密钥不进 Git。
- HTTPS、Secure Cookie 和随机会话密钥已启用。
- 对象存储私有读，下载链接短时有效。
- 健康检查、日志、备份与恢复演练可用。
- 至少两位维护者知道停站、回滚和导出数据的方法。
- 已用虚构账号分别验证管理员、成员、观察员权限。
