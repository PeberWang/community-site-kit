# 社群建设手册

## 从一个真实循环开始

选择一个每两周至少发生一次的问题，例如“新成员总在问同样的入门问题”。让三到五位成员贡献经验，由一位管理员整理并发布第一篇指南。观察两周：是否有人阅读、补充、纠错？只有循环成立后再扩展栏目。

## 把贡献变成关系

不要只收“文件”。每次贡献至少记录归属标签，以及心得、推荐理由或附件中的一项；对附件追问“适合谁、怎样用、有什么局限”。展示贡献者时尊重其署名选择，也允许撤回。

## 人工维护真相源

正式指南以 Markdown 正文为真相源。Agent 读取当前版本和新证据后生成候选稿；确定性检查通过后，管理员查看差异并发布。人工修改必须保留，旧候选稿不能覆盖新版本。

## 区分两种公共性

文章、活动、贡献会进入正式知识或代表组织，应先审后发。广场承担日常交流，可以先发后管，但必须有举报、删除和管理员值守规则。不要把两类流程混成一个“万能发布”。

## 建立交接而不是英雄主义

至少两人知道怎样创建邀请码、审核内容、备份数据和恢复服务。每月导出一次可读数据，每学期复核管理员名单、云账单、域名和模型凭据。换届先做演练，再转交权限。

## 衡量有用，而不是热闹

早期可关注：重复问题是否减少、贡献从提交到发布需要多久、指南多久被纠错一次、多少内容有明确负责人。不要把浏览量当作唯一目标，也不要为了活跃度牺牲成员安全。
