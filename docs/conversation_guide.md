# 怎样和 Agent 聊

低技术能力不等于低决策能力。你最重要的工作，是讲清社群关系、实际摩擦和不可接受的后果；Agent 再把它们翻译成产品和代码。

## 推荐开场

> 我想为【谁】做一个网站，当前最痛的问题是【什么】。我希望你使用 $build-community-hub，一次问一个问题。每轮先复述你的理解，再说明这个答案会影响什么。需求没有确认前不要部署或接触真实数据。

## 值得聊深的六组问题

### 1. 人

谁是日常使用者、贡献者、审核者、只读观察者？谁会被遗漏？发生争议时谁有最终决定权？

### 2. 场景

成员现在靠群聊、网盘、共享文档还是口耳相传？最常重复问的问题是什么？哪一步最耗人？

### 3. 内容

哪些内容需要长期演化，哪些是有时效的通知，哪些只是轻量讨论？一份好贡献最低需要哪些上下文？

### 4. 治理

什么必须先审后发？什么可以先发后管？谁可以删除、纠错、恢复旧版？如何处理署名、撤回和争议？

### 5. 风险

是否涉及未成年人、成绩、政治立场、健康、联系方式、内部文件或版权材料？哪些内容禁止发送给第三方模型？

### 6. 持续性

谁每周维护？毕业或换届后怎么交接？如果 Agent、云服务或发起人离开，社群能否导出数据继续运行？

## 让对话不失控的句式

- “先给我最小方案和以后可加的方案，不要一次做完。”
- “把这个决定写进决策记录，并告诉我怎样撤回。”
- “请用成员能感受到的结果解释，不要只报技术名词。”
- “列出你正在假设但我还没有确认的地方。”
- “先用虚构数据演示，未经我确认不要导入真实资料。”
- “每完成一阶段都跑测试，并用一段普通话告诉我验收什么。”

## 红旗

如果 Agent 准备直接公开仓库、上传真实数据、自动发布 AI 正文、替你决定审核规则、索要不必要的密钥，或者用“以后再说”跳过备份与交接，应立刻暂停并要求它回到风险清单。
