# 维护与升级

## 每周

- 查看待审核内容、举报和失败任务。
- 抽查一条新指南是否保留来源与人工修改。
- 检查磁盘、对象存储和异常日志。

## 每月

- 备份 `data/db`、`data/guides` 与附件，并完成一次抽样恢复。
- 更新依赖前阅读安全公告，在测试环境验证。
- 检查管理员、邀请码、模型和存储权限是否仍最小化。
- 询问成员：哪个流程最费力，哪个模块已经无人负责。

## 每学期或换届

- 导出一份人类可读的 Markdown/JSON 归档。
- 轮换凭据，移除离任管理员，更新联系人。
- 让新维护者独立完成一次部署、恢复和内容回滚。
- 记录保留、关闭或新增模块的理由。

## 升级原则

生产数据永远不是代码更新的副产品。升级前备份，代码通过 Git 合并，迁移脚本先在副本上运行。任何自动生成的指南都只能进入候选状态；管理员发布前必须查看差异。
